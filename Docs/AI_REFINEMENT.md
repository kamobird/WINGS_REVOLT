# WINGS REVOLT — 認識と協調AIの改訂

## 起動と確認

新しい実行版は `Builds/AIRefined/WINGS_REVOLT_AI.exe`。最初のα版は `Builds/Alpha` に残しています。Unityプロジェクトのコードは改善版へ更新済みです。Unityではこれまでの `Assets/Wings/Scenes/WingsAlpha.unity` から再生できます。

戦闘中の **F1** で、操作キャラの次の編成番号にいる味方AIの状態を表示します。操作を切り替えると、表示する味方も変わります。命令・状態・判断理由・目視数・射撃許可・NavMesh経路・記憶の鮮度を確認できます。これは観察用の表示であり、AIへ追加情報を渡すものではありません。

Unityでは、実行中のキャラの `AIBody` を選択してGizmosを有効にすると、視野扇形・直接目視した相手への線・記憶地点を表示します。Inspectorの `DebugState` と、`WINGS ALLY AI` で始まる状態遷移ログも使えます。

## 認識の契約

全体のキャラクター登録簿は、センサーの候補列挙と局所的な身体回避に使います。登録されているだけでは戦闘対象として知っていることにはなりません。戦闘判断は、センサーが生成したContactか、期限付きの観測報告だけを受け取ります。

| 項目 | 初期値・扱い |
| --- | --- |
| 味方の水平視野 | 120度 |
| 敵の水平視野 | 110度 |
| 上下の視野 | 120度 |
| 味方の視認距離 | ペンギン・フクロウ34m、タカ55m、カラス43m、ツバメ25m |
| 敵の視認距離 | 通常20m、射撃型25m |
| センサー更新 | 約0.12秒。初回を個体ごとにずらす |
| 遮蔽 | 胴・肩・頭の3点へのLinecast。いずれかが露出していれば発見可能 |
| 発砲許可 | 現在の視認を再確認し、銃口から観測位置への射線と武器射程を追加確認 |
| 目視の記憶 | 最後に観測した位置を固定し、3秒で失効 |
| 味方からの報告 | 元の観測位置・観測時刻を保持し、1.5秒で失効 |
| 信頼度 | 直接視認は1。記憶は線形減衰。報告は0.65を上限に線形減衰。0.2未満は捜索に使わない |
| 聴覚 | 今回は未実装 |

頭が見える場合でも、銃口が壁に隠れていれば攻撃できません。見失った相手の生きたTransformへ追跡先を更新せず、記録した地点へ向かいます。報告先へ移動した味方も、自分で相手を再発見するまでは発砲しません。伝聞を新しい目視として再送して、情報の寿命を延ばすこともありません。

敵は最後に見た相手の地点を最大2秒ほど調べ、その後は本来の任務であるタワーへの進行へ戻ります。センサー側の記憶は3秒で失効します。

タカのULTでは、能力の仕様として壁の遮蔽を無視します。距離と視野角は維持します。カラスの全敵攻撃など、発動後の能力効果が広範囲へ及ぶことは、AIが全敵位置を判断材料として使うこととは区別しています。

タワー位置、NavMesh、味方への命令、編隊のリーダー位置は、任務開始時に与えられた地図・通信情報として扱います。未発見の敵の現在位置とは分離しています。

## 命令と判断

| 大命令 | 行動 |
| --- | --- |
| 追従 | リーダー後方の別々の編隊位置を取る。12mを超えたら帰還を優先。移動中でも直接見えて射撃条件を満たす敵には射撃できる |
| 防衛 | タワー周囲の別々の警戒位置を取る。11mの行動範囲へ戻り、外側へ敵を追い過ぎない |
| 攻撃 | 目視した敵へ積極的に接近。敵が不明なら巡回。古い観測・味方の報告があれば、信頼度の高い地点を調べる |

大命令と下位のFSM状態は別に保持します。状態は Guard、Patrol、Regroup、Pursue、Reposition、Attack、Investigate、Reload。ダウンと復帰は既存のキャラ状態で管理し、復帰時に認識・経路・担当予約を初期化します。

目標選択は、直接見えている候補だけを次の効用で比較します。

`45 − 適正距離との差 + 拠点への接近度×25 − 他の味方の担当数×8`

0.65秒の保持時間と、原則8点以上の切替優位を使い、小さな条件差で目標が頻繁に入れ替わることを抑えます。現在の相手を失った場合は、その保持時間に縛られず、見える別の候補へ切り替えられます。効用評価は攻撃目標の選択に使い、行動遷移そのものはFSMで扱っています。GOAP・学習・未来の先読みは今回の採用対象にしていません。

固有能力は、直接見えている敵の距離・まとまりと、自分の資源に応じて判断します。カラスの強化矢の残数、タカのデコイの再発動、フクロウの爆撃、ツバメのゲージなどは既存の能力処理へ接続しています。

## 移動と集団

実マップのColliderから、Unity AI NavigationのNavMeshを任務開始時に生成します。個体のPathMotorは約0.4秒間隔を基準に経路を再計算し、目的地が変わった場合も再計算します。歩行は既存のCharacterControllerで行い、NavMeshの経路に局所回避を合成します。

遮蔽物の当たり判定はWallレイヤー（8）を使います。新しい壁・建物を追加するときも、視界と移動を遮るColliderをこのレイヤーに指定してください。見た目だけのモデルにはColliderを追加せず、キャラのルートに身体判定を残します。ペンギンの氷壁にはcarving付きNavMeshObstacleを付け、経路へ反映しています。

群衆の近傍検索は2.5mのセルで空間分割します。近くの身体から離れる方向を計算し、壁を挟む身体は回避計算から外します。この近傍情報を戦闘相手の発見情報へ変換することはありません。

包囲位置は相手の周囲8方向、タワーの周囲12方向から期限付きで予約します。同じ目標へ向かう複数体には別の位置を割り当て、担当しなくなった予約は0.8秒で失効します。狭い通路では物理的に列になる場合があります。開けた場所でも一つの座標だけへ集まり続ける挙動を緩和するための仕組みです。

## 設定とコード

`Assets/Wings/Resources/WingsAI.asset` で、敵味方の視野角、センサー周期、記憶・報告の寿命、遮蔽レイヤー、追従・防衛の範囲、目標保持時間、切替差を調整できます。既存のキャラクター設定とモデル差し替え方式はそのまま使えます。

| ファイル | 責務 |
| --- | --- |
| AIConfiguration.cs | 変更可能なAI設定 |
| AIPerception.cs | 身体登録、視覚センサー、Contact、記憶、共有報告、位置予約 |
| AIBrains.cs | 敵味方のFSM、命令範囲、目標の効用評価、能力の選択 |
| AINavigation.cs | 任務のNavMesh生成、個体経路、セル近傍の回避 |
| AIDebugUI.cs | F1の観察表示 |
| AIVerification.cs | 認識・協調に特化した自動検証 |
| PlayerAgent.cs / Combat.cs | 新しい判断を移動と既存の攻撃処理へ接続 |

Unityの `WINGS > Build Refined AI` で改善版をビルドできます。既存シーンを作り直すことなく、AI設定の作成とビルドを行います。

## 設計シートとの対応

開いている「ゲームAI課題制作_設計シート_ex.xlsx」の設計書を具体化し、技術選択で15項目を採用しています。内訳は認識3、身体3、協調5、知能4。技術名・分野・章番号は提供された区分を維持し、F～I列に本作での目的・実装・期待挙動・検証方法を記入しました。

提出用まとめは採用項目へ数式で連動するようにし、別作品の古い記入例を置き換えています。表示容量は既存の22行を維持しています。

## 検証

`--wings-ai-test --wings-report <出力先>` で認識・協調の検証を実行できます。`--wings-smoke` は従来の5キャラの能力と画面遷移の回帰確認です。通常の起動では検証処理は動きません。

実測結果と画像は `Docs/AI_Verification` と `Docs/AI_Regression` に保存します。時間を5倍速にしたAI操作での通し確認を含みます。手動の操作感や最終バランスは、引き続きプレイしながら調整する範囲です。

2026年10月22日の改善版で、追加の認識・協調検証33項目と既存の回帰確認48項目が成功しました。報告JSONの配列には、それぞれ2件のステージ結果記録も含まれます。ステージAは3ウェーブ・94撃破、ステージBは4ウェーブ・196撃破でクリアし、いずれもタワーHP1500を維持しました。通し確認では余裕のある結果になっているため、敵の強さや出現密度は最終調整前です。

実装APIの参考: [Unity NavMeshSurface](https://docs.unity.cn/Packages/com.unity.ai.navigation@1.1/api/Unity.AI.Navigation.NavMeshSurface.html)、[Unity NavMesh.CalculatePath](https://docs.unity.com/en-us/engine/6000.7/script-reference/unityengine/ai/navmesh/calculatepath)。このプロジェクトでは導入済みAI Navigation 2.0.10のソースも確認しています。
